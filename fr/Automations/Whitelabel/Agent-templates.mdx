## Présentation

Les **Modèles d’agent personnalisés** vous permettent de préparer une configuration d’agent « prête à l’emploi » que vos **sous-comptes** peuvent appliquer quand ils créent de nouveaux agents. Au lieu de tout configurer à chaque fois, vous choisissez les paramètres inclus dans le modèle, vous préremplissez leurs valeurs, et vos utilisateurs complètent seulement ce qui est nécessaire.

Utilisez cette section quand vous voulez :
- **Un comportement cohérent** des agents sur plusieurs sous-comptes.
- Une prise en main plus rapide pour les nouveaux utilisateurs.
- Une sélection de configurations d’agent « approuvées ».

## Ouvrir Modèles d’agents

Vous les trouverez dans la Plateforme white label, dans **Gestion du contenu** ([ouvrez-les ici](https://app.callin.io/cms/agent-templates)).

## Créer un modèle

1. Ouvrez **Modèles d’agent personnalisés**.
2. Cliquez sur **Créer un modèle**. Un panneau s’ouvre à droite.
3. Remplissez les informations du modèle (les deux sont obligatoires) :
   - **Nom du modèle** : un nom clair que vos sous-comptes reconnaîtront.
   - **Description** : une courte explication de l’usage du modèle.
4. Choisissez les champs à inclure et définissez leurs valeurs par défaut (voir ci-dessous).
5. Cliquez sur **Créer un modèle** en bas du panneau.

> **Astuce :** Utilisez des noms qui décrivent la tâche, pas l’équipe. Exemple : **« Support client entrant »** plutôt que **« Support - Équipe A »**.

## Choisir ce que les sous-comptes peuvent configurer

Dans **1. Sélectionner les champs**, vous verrez une liste de cases à cocher.\
**Cochée = incluse dans le parcours du modèle pour les sous-comptes.**\
Les champs non cochés ne font pas partie du modèle.

### Informations de base

Vous pouvez inclure des champs comme :
- **Nom de l’agent**
- **Message d’accueil**
- **Prompt système**
- **Direction d’appel**
- **Durée max de l’appel (minutes)**
- **Variables dynamiques**
- **Fuseau horaire**
- **Modèle IA**
- **Enregistrer les appels**
- **Détection de messagerie vocale**
- **L’utilisateur parle d’abord**

> **Important :** N’incluez que les champs que vous voulez vraiment laisser modifier aux sous-comptes. Moins de champs signifie généralement moins d’erreurs.

### Voix et langue

Vous pouvez inclure des champs comme :
- **Langue principale**
- **Langues secondaires**
- **Voix**
- **Vitesse de parole**
- **Température**

> **Astuce :** Si vous travaillez dans plusieurs régions, incluez **Langue principale** et **Fuseau horaire** pour que les sous-comptes s’adaptent vite sans dénaturer le modèle.

### Action d’appel

Vous pouvez inclure des champs comme :
- **Planifier un rendez-vous**
- **Fournisseur de calendrier**
- **Transférer l’appel**
- **Envoyer un e-mail**
- **Désinscription**
- **Extraction de données**
- **Entités d’extraction**
- **Webhook post-appel**
- **URL du webhook**
- **Nombre de tentatives**
- **Délai de tentative (minutes)**

> **Erreur fréquente :** Inclure **URL du webhook** pour les sous-comptes alors que vous voulez garder ce réglage sous le contrôle de votre organisation. Si vous avez besoin d’un suivi centralisé, n’exposez pas les champs de webhook.

### Valeurs par défaut

Dès que vous cochez un champ, il apparaît dans **2. Définir les valeurs par défaut**. Vous y préremplissez sa valeur : les sous-comptes partent de celle-ci quand ils créent un agent avec ce modèle.

Chaque champ affiche un court texte d’aide. Par exemple :

- **Nom de l’agent** : le nom de l’agent (le sous-compte peut le modifier).
- **Message d’accueil** : le premier message que dit l’agent au début de l’appel.
- **Prompt système** : les instructions qui définissent le comportement de l’agent.
- **Fuseau horaire** : il influence les réponses liées à l’heure. Il commence à **UTC**.
- **Langue principale** : la langue principale que l’agent utilisera.
- **Voix** : la voix de l’agent, choisie dans la liste ElevenLabs.

## Modèles pré-déployés

En bas du panneau, vous verrez **Pré-déployé**.

Si vous l’activez, un agent sera **automatiquement créé avec ce modèle** dans les comptes utilisateurs nouvellement inscrits.

> **Important :** Activez-le uniquement pour votre modèle « de démarrage par défaut ». Sinon, les nouveaux utilisateurs pourraient recevoir des agents qu’ils ne voulaient pas créer.

## Statut du modèle

Vous verrez aussi **Statut du modèle**. Il est activé par défaut.\
Seuls les modèles **actifs** sont visibles par les sous-comptes.

Utilisez-le pour :
- Masquer temporairement d’anciens modèles sans les supprimer.
- Ne laisser disponibles que vos modèles recommandés.

Pour modifier un modèle plus tard, cliquez sur **⋮** dans la colonne **Actions** :

- **Modifier le modèle** ouvre le même panneau, pour changer les champs, les valeurs par défaut, **Pré-déployé** ou **Statut du modèle**.
- **Supprimer le modèle** le retire.

## Exemple : une configuration de modèle réaliste

Voici une façon réaliste de structurer un modèle pour un agent de support entrant :

**Nom du modèle :** Support client entrant\
**Description :** Répond aux questions entrantes, recueille les informations de base et transfère les cas urgents.

**Champs à inclure (recommandés) :**
- Nom de l’agent
- Message d’accueil
- Prompt système
- Fuseau horaire
- Langue principale
- Voix
- Transférer l’appel (seulement si votre processus prévoit une escalade)

**Valeurs par défaut (exemple) :**
- Nom de l’agent : « Accueil »
- Message d’accueil : « Bonjour, merci de votre appel. Comment puis-je vous aider ? »

> **Astuce :** Si vos sous-comptes ne doivent pas changer le comportement principal, incluez le **Prompt système** mais évitez d’exposer trop de réglages avancés à la fois.

## Notes et limites

- Ce que voient les sous-comptes peut dépendre des permissions de leur rôle et de leur forfait.
- Certaines options et libellés peuvent varier légèrement selon les comptes.

Vous pouvez créer plusieurs modèles par cas d’usage (par exemple **Qualification commerciale**, **Prise de rendez-vous**, **Tri du support**) pour que les sous-comptes partent toujours du plus proche.
