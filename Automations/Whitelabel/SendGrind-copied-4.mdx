## Pourquoi SendGrid est important
Imaginez qu’un utilisateur s’inscrive à votre application. Il s’attend à recevoir un e-mail de confirmation en quelques secondes. Si cet e-mail n’arrive jamais, sa première expérience est déjà compromise. C’est la même chose pour les réinitialisations de mot de passe ou les notifications : sans un service d’e-mail fiable, votre application paraît peu sérieuse.

C’est exactement ce que SendGrid résout. C’est une plateforme professionnelle de délivrabilité e-mail qui garantit que vos messages arrivent dans la boîte de réception plutôt que dans les spams. En connectant SendGrid, vous donnez à votre application un « facteur » vérifié qui livre toujours à temps.

Pour que cela fonctionne, votre application a besoin de deux éléments :
- **Une clé API** → c’est le moyen sécurisé pour que votre application se connecte automatiquement à SendGrid.
- **Une adresse e-mail d’expéditeur** → c’est l’adresse « De » que les utilisateurs verront, et elle doit avoir un aspect professionnel.

## Étape 1 : Ouvrir le CMS et aller sur SendGrid
Commencez par vous connecter à votre CMS. Dans le menu de gauche, cliquez sur **Integrations**, puis choisissez **SendGrid**. Vous verrez deux champs : `api_key` et `sender_email`.

Pensez à ces deux champs comme à un cadenas et une étiquette :
- La **clé API** est le système de verrouillage qui donne à votre application l’accès à SendGrid.
- L’**e-mail d’expéditeur** est l’étiquette qui dit à vos utilisateurs « cet e-mail vient de nous ».

Sans les deux, votre application ne peut pas envoyer d’e-mails.

## Étape 2 : Créer votre clé API dans SendGrid
Maintenant, récupérons la clé qui « déverrouille » SendGrid pour votre application.

1. Connectez-vous à `https://app.sendgrid.com`.
2. Allez dans **Settings > API Keys**.
3. Cliquez sur **Create API Key**. Donnez-lui un nom clair, par exemple « App Integration ».
4. Choisissez les permissions. Si vous n’êtes pas sûr, sélectionnez **Full Access**, mais au minimum vous avez besoin de **Mail Send**.
5. Copiez la clé API.

Elle ressemble à ceci :
`SG.VOTRE_EXEMPLE_DE_CLE_API`

Cette clé est utilisée à chaque envoi d’e-mail. Si la clé est incorrecte, **tous** les e-mails échoueront. Traitez-la comme un mot de passe : confidentielle et sécurisée.

## Étape 3 : Ajouter la clé API dans le CMS
De retour dans votre CMS, dans la section SendGrid :
1. Cliquez sur **Add API Key**.
2. Laissez **Key Name** sur `api_key` (ne le modifiez pas).
3. Collez votre clé SendGrid dans **Key Value**.
4. Ajoutez une description, par exemple « Main SendGrid Key ».
5. Cochez **Active** puis cliquez sur **Save Key**.

Votre application sait maintenant comment se connecter à SendGrid.

## Étape 4 : Ajouter l’adresse e-mail d’expéditeur
La question suivante est : « Quand mon application envoie un e-mail, de qui a-t-il l’air de provenir ? »

C’est ici que vous définissez `sender_email`. Il doit être professionnel et cohérent avec votre marque. Par exemple :
- `support@votreentreprise.com`
- `notifications@votreentreprise.com`

Évitez les adresses personnelles Gmail ou Outlook : elles font moins professionnel et sont plus souvent filtrées comme spam.

Dans le CMS, cliquez à nouveau sur **Add API Key** et remplissez comme suit :
- **Key Name :** `sender_email` (ne le modifiez pas).
- **Key Value :** l’adresse e-mail choisie.
- **Description :** par exemple « Support Email Address ».
- Cochez **Active** et enregistrez.

Important : SendGrid n’enverra des e-mails « De » que depuis des domaines que vous avez vérifiés. Cela signifie que si vous utilisez `support@votreentreprise.com`, vous devez d’abord authentifier `votreentreprise.com` dans SendGrid. Sinon, les e-mails risquent d’aller directement en spam.

## Étape 5 : Tester votre configuration
Ne vous contentez pas de faire confiance aux réglages : testez-les.

Essayez de créer un compte de test dans votre application ou demandez une réinitialisation de mot de passe. En quelques secondes, vous devriez recevoir l’e-mail dans votre boîte de réception.

Si vous ne le voyez pas :
- vérifiez d’abord les spams,
- puis confirmez que votre domaine d’expéditeur est bien vérifié dans SendGrid.

## Erreurs fréquentes
- **Laisser les clés inactives :** si ce n’est pas marqué **Active**, votre application n’essaiera pas d’envoyer.
- **Modifier les noms de clés :** le système ne reconnaît que `api_key` et `sender_email`.
- **Utiliser un domaine non vérifié :** authentifiez toujours votre domaine d’expéditeur dans SendGrid.
- **Copier la mauvaise clé :** SendGrid n’affiche la clé API complète qu’une seule fois. Si vous la perdez, vous devez en générer une nouvelle.

## Votre application est prête à envoyer des e-mails
Avec SendGrid connecté, vos utilisateurs recevront toujours leurs confirmations, réinitialisations et mises à jour à temps. Pas d’envoi manuel, pas de doute sur le spam : une communication fluide et fiable.

Une fois cette étape terminée, vous supprimez l’une des plus grandes frustrations des nouveaux utilisateurs : « Je me suis inscrit, mais je n’ai jamais reçu l’e-mail. »
