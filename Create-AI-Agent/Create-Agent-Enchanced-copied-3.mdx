## Resumen general

La página de **Agentes de IA** es el punto de partida para crear y gestionar los agentes de tu cuenta. Desde aquí puedes ver todos tus agentes en un solo lugar, abrir cualquiera para editarlo y detectar rápidamente qué configuraciones siguen incompletas.

En esta vista normalmente puedes:

- crear un agente nuevo
- filtrar agentes según el tipo de llamada
- buscar un agente por nombre
- comprobar si un agente ya tiene un número asignado
- entrar directamente en la configuración para terminar el ajuste

Esto resulta útil cuando gestionas varios flujos distintos. Por ejemplo, una clínica puede tener un agente para recordar citas, otro para responder llamadas entrantes y otro para recuperar oportunidades perdidas. Separarlos por función hace que las pruebas, la revisión y los cambios futuros sean mucho más sencillos.

Para crear un agente nuevo, haz clic en el botón para crear un agente, elige si quieres empezar desde cero o usar una plantilla, escribe un nombre claro y confirma la creación.

> **Consejo:** Usa nombres que describan el trabajo real del agente, como **Agente de recordatorio de citas** o **Agente de captación de pacientes**, en lugar de nombres genéricos como “Prueba”.

## Dirección de la llamada

La primera configuración es **Dirección de la llamada**. Esto define si el agente se utiliza para **realizar llamadas, responder llamadas o hacer ambas cosas con la misma configuración**.

Puedes elegir:

- **Saliente** si el agente va a llamar a los usuarios.
- **Entrante** si el agente va a responder llamadas entrantes.
- **Ambas direcciones** si el mismo agente debe gestionar ambos casos de uso.

Elige esto en función del flujo de trabajo real, no solo de lo que parezca más flexible. Un agente de recordatorio de pagos suele ser **saliente**, mientras que una recepción, una línea de soporte o una línea de reservas suele ser **entrante**.

Con **Saliente**, el agente inicia la conversación. Esto normalmente significa que el primer mensaje es más directo y orientado al objetivo, porque el agente ya sabe por qué está llamando. Por ejemplo, un agente saliente puede llamar para confirmar una cita, hacer seguimiento de un presupuesto, recordar a un cliente una factura pendiente o calificar un nuevo contacto después de que haya enviado un formulario.

Un ejemplo sencillo de uso saliente sería un asistente de clínica llamando a un paciente para confirmar la cita de mañana. En ese caso, la apertura puede ir directamente al punto porque la llamada tiene un propósito claro desde el inicio.

Con **Entrante**, el usuario inicia la conversación. Esto significa que el agente debe estar preparado para entender distintas intenciones, guiar a la persona que llama y hacer preguntas de aclaración antes de avanzar. Los agentes entrantes son habituales en flujos de recepción, líneas de reservas, soporte básico, preguntas sobre horarios y filtrado de primer contacto.

Un ejemplo sencillo de uso entrante sería la línea de una clínica dental, donde las personas que llaman pueden querer reservar, reprogramar, preguntar por los horarios o comprobar si un tratamiento está disponible. En ese escenario, el agente debe sonar abierto y útil porque no conoce de antemano el motivo de la llamada.

Con **Ambas direcciones**, el mismo agente gestiona llamadas salientes y entrantes. Esto es útil cuando el flujo de trabajo es muy parecido en ambos casos y el mismo tono, objetivo y lógica funcionan bien de las dos maneras.

> **Importante:** Un agente de **Ambas direcciones** utiliza el **mismo saludo** y el **mismo guion** tanto para llamadas entrantes como para llamadas salientes.

Este es un punto de confusión muy común. Algunas personas creen que deben añadir un saludo y un guion para llamadas entrantes, y otro saludo y otro guion para llamadas salientes dentro del mismo agente. **No** es así como funciona esta configuración.

Cuando eliges **Ambas direcciones**, estás creando **un solo agente** con **un comportamiento compartido**. Eso significa que el saludo y el guion deben escribirse de una forma más neutra para que tengan sentido tanto si la llamada la inició el agente como si la inició el usuario.

Por ejemplo, un saludo neutro puede funcionar para ambos casos si presenta claramente al negocio y luego se adapta de forma natural a la conversación. El guion también debe evitar suposiciones que solo encajen con una dirección. Si el guion dice algo demasiado específico como “Le llamo para recordarle su factura pendiente”, puede sonar incorrecto en una llamada entrante en la que el cliente llamó primero por un motivo distinto.

Una mejor forma de trabajar con ambas direcciones es hacer que el agente sea flexible. Por ejemplo, un asistente de una inmobiliaria podría saludar, identificar a la empresa y luego continuar según si la conversación trata sobre el seguimiento de una consulta previa sobre una propiedad o sobre una nueva pregunta entrante acerca de disponibilidad.

Otro ejemplo es un pequeño salón que quiere un solo agente para responder preguntas entrantes y también devolver llamadas a clientes sobre la agenda. Eso puede funcionar con **Ambas direcciones** si el mismo tono general y el mismo flujo tienen sentido en ambos casos.

> **Consejo:** Si el agente necesita comportarse de forma diferente según la dirección de la llamada, normalmente es mejor crear **dos agentes independientes**: uno para **Entrante** y otro para **Saliente**.

Esta es la mejor opción cuando cada dirección necesita una apertura distinta, un tono distinto, objetivos distintos o una lógica de calificación diferente. Por ejemplo, un agente comercial que realiza llamadas salientes de seguimiento puede necesitar un guion más persuasivo y estructurado, mientras que un agente de recepción para llamadas entrantes puede necesitar un flujo más calmado y abierto.

Otro buen ejemplo es un flujo de cobro de deudas. La versión saliente puede necesitar un recordatorio muy específico y seguro en términos de cumplimiento, mientras que la versión entrante puede necesitar verificar primero la identidad y después responder preguntas sobre el pago. Aunque ambas pertenezcan al mismo proceso de negocio, normalmente funcionan mejor como agentes separados.

> **Error común:** Elegir **Ambas direcciones** solo para cubrir más casos, incluso cuando la experiencia entrante y la saliente deberían sentirse diferentes.

Como regla general, usa **Ambas direcciones** solo cuando un único saludo compartido y un único guion compartido puedan gestionar realmente bien ambos tipos de llamada. Si no es así, crea un agente por dirección para que cada experiencia se sienta natural e intencional.

### Duración máxima de la llamada

La duración máxima de la llamada controla cuánto puede durar una conversación antes de cerrarse automáticamente.

Esto te ayuda a:

- mantener llamadas eficientes
- evitar conversaciones demasiado largas
- controlar mejor el consumo

Como referencia, una llamada corta de recordatorio puede necesitar entre **3 y 5 minutos**, mientras que una llamada de reserva o de cualificación puede necesitar entre **5 y 10 minutos**.

### Mensaje de bienvenida

El mensaje de bienvenida es lo primero que escucha la persona al comenzar la llamada. Debe ser corto, claro y relacionado con la función real del agente.

Una estructura sencilla que suele funcionar bien es:

- saludo
- identificación
- motivo de la llamada
- invitación a continuar

Ejemplo:

**Hola, te llamo de Clínica Northwind para ayudarte a confirmar tu próxima cita. ¿Te viene bien continuar ahora?**

Si usas variables dinámicas, puedes reutilizar la misma estructura en varios agentes sin tener que reescribirla completa cada vez.

### Instrucciones de conversación

Las instrucciones de conversación son una de las partes más importantes de la configuración. Mientras el mensaje de bienvenida abre la llamada, estas instrucciones definen cómo debe comportarse el agente durante el resto de la interacción.

Una forma simple de entenderlo es esta:

- el **mensaje de bienvenida** inicia la conversación
- las **instrucciones de conversación** guían todo lo que ocurre después

El ejemplo que aparece por defecto en Callin es útil porque muestra una estructura recomendada. No hace falta copiarlo completo tal como viene, pero sí conviene entender por qué está organizado de esa manera.

#### Cómo suele estar estructurado

El ejemplo base suele dividirse en bloques como estos:

- personalidad
- entorno
- tono
- objetivo
- límites
- herramientas

Cada bloque cumple una función concreta.

#### Personalidad

Aquí explicas quién es el agente y cómo debe presentarse.

Por ejemplo:

- un asistente de recepción
- un asistente de reservas
- un asistente de seguimiento
- un asistente de cualificación

Esto ayuda a que el agente mantenga una identidad consistente durante toda la llamada.

#### Entorno

Aquí explicas en qué contexto ocurren las conversaciones.

Por ejemplo:

- llamadas telefónicas breves donde la claridad es importante
- llamadas para reservar citas
- llamadas de seguimiento
- llamadas para resolver dudas simples

Este bloque ayuda al agente a entender el tipo de interacción que está gestionando y a no responder como si fuera un asistente genérico.

#### Tono

Aquí defines cómo debe sonar el agente.

El ejemplo por defecto deja claro que, en llamadas de voz, normalmente conviene que el agente:

- hable de forma educada y concisa
- use confirmaciones breves
- mantenga un tono cálido pero profesional
- haga pausas naturales
- pronuncie con claridad datos estructurados, como correos electrónicos

Esto es importante porque una llamada telefónica necesita respuestas más claras y directas que un chat escrito.

#### Objetivo

Aquí explicas qué debe lograr el agente.

Por ejemplo:

- confirmar una cita
- responder preguntas frecuentes
- recoger datos básicos
- cualificar a un posible cliente
- llevar la conversación al siguiente paso correcto

Sin un objetivo claro, el agente puede sonar bien, pero no cumplir su función.

#### Límites

Aquí indicas lo que el agente no debe hacer.

El ejemplo base deja ver reglas muy útiles, como:

- no compartir información sensible
- no inventar respuestas
- reconocer límites cuando no pueda ayudar
- mantener la calma si el usuario se frustra
- seguir centrado en la necesidad real del usuario

Esta parte es clave si el agente va a hablar directamente con clientes o pacientes.

#### Herramientas dentro de las instrucciones

El ejemplo también incluye un bloque para indicar si el agente debe trabajar solo mediante conversación o si puede apoyarse en herramientas ya configuradas.

Si el agente debe resolver todo hablando, conviene decirlo de forma explícita. Si debe usar una herramienta, esa herramienta tiene que existir antes de vincularla al agente.

### Cómo escribir bien las instrucciones de conversación

Unas buenas instrucciones deben explicar el trabajo del agente con lenguaje claro y práctico.

En lugar de escribir algo demasiado general como:

**Sé útil y educado.**

Es mejor escribir algo más específico, por ejemplo:

**El agente es un asistente telefónico de una clínica dental. Debe ayudar a confirmar citas, responder dudas básicas sobre horarios, mantener un tono educado y conciso y guiar a la persona al siguiente paso cuando la solicitud quede fuera de su alcance.**

Esto funciona mejor porque define:

- quién es el agente
- qué tipo de llamada maneja
- cómo debe sonar
- qué resultado debe buscar
- qué debe evitar

### Optimizar las instrucciones

Junto al área de instrucciones, Callin incluye una opción para **optimizar las instrucciones**. Al abrirla, aparece una ventana donde puedes escribir qué tipo de mejora quieres aplicar sobre el texto actual.

Esto es útil cuando ya tienes una base, pero quieres mejorarla sin rehacer todo desde cero.

Por ejemplo, puedes pedir que el sistema:

- lo haga más corto y claro
- use un tono más cercano
- añada manejo de objeciones
- suene más profesional
- simplifique instrucciones demasiado largas

Un ejemplo práctico sería pedir algo como:

**Hazlo más conciso, mantén un tono cálido y profesional y añade un manejo más claro de objeciones frecuentes.**

Después de optimizarlo, revisa siempre el resultado antes de guardar para confirmar que sigue alineado con la función real del agente.

> **Importante:** Optimizar las instrucciones ayuda a mejorar la redacción, pero no sustituye la revisión humana. Antes de guardar, confirma que el texto final realmente coincide con el comportamiento que quieres.

### Variables dinámicas

Las variables dinámicas te permiten reutilizar datos como el nombre del agente o del negocio en distintos puntos de la configuración.

Esto es útil cuando quieres mantener la misma estructura en varios agentes y cambiar solo algunos valores concretos.

### Zona horaria y modelo

Más abajo puedes configurar la zona horaria y el modelo que usará el agente.

La zona horaria es importante cuando el agente:

- menciona horarios
- programa citas
- hace referencia a horas locales

El modelo influye en cómo genera sus respuestas. Según tu cuenta o tu plan, algunas opciones pueden variar.

### Base de conocimiento

La base de conocimiento le da al agente información de apoyo para responder con mayor precisión.

Si todavía no la configuraste antes, debes hacerlo aquí: [Base de conocimiento](https://app.callin.io/knowledge-base)

Este es el lugar adecuado para añadir contenido como:

- preguntas frecuentes
- políticas
- precios
- detalles de servicios
- información útil para responder dudas comunes

Por ejemplo, una clínica puede incluir horarios de atención, reglas de cancelación, seguros aceptados e instrucciones previas a una cita.

Una regla práctica es esta:

- usa las **instrucciones de conversación** para comportamiento y reglas
- usa la **base de conocimiento** para hechos e información de referencia

### Herramientas

Las herramientas permiten que el agente use funciones adicionales durante una llamada.

Si todavía no configuraste la herramienta antes, debes hacerlo aquí: [Herramientas](https://app.callin.io/tools)

Esto es importante porque el agente no puede usar correctamente una herramienta que aún no existe o que no fue configurada antes.

Un flujo recomendable es este:

1. configurar la herramienta en [Herramientas](https://app.callin.io/tools)
2. volver al agente
3. vincular la herramienta
4. probar la conversación completa

Por ejemplo, si quieres que el agente consulte información externa o ejecute una acción específica, primero tienes que dejar esa herramienta preparada.

### Ajustes de llamada

En esta misma sección también puedes encontrar ajustes adicionales, como:

- grabación de llamadas
- detección de buzón de voz
- opción para que el usuario hable primero

Estos ajustes terminan de definir cómo será la experiencia real cuando el agente esté activo.

> **Error común:** Escribir unas instrucciones demasiado generales y pensar que con eso el agente sabrá cuándo usar una herramienta. El objetivo debe quedar claro en las instrucciones y la herramienta debe estar configurada antes.

### Idioma principal e idioma secundario

Empieza eligiendo el idioma principal. Debe coincidir con el idioma que la mayoría de las personas usará al hablar con el agente.

También puedes añadir un idioma secundario si el agente necesita atender en más de un idioma.

Por ejemplo:

- una clínica local puede necesitar solo un idioma principal
- un negocio que atiende a distintos públicos puede combinar dos idiomas

### Voz

La voz define cómo sonará el agente en la llamada.

En el selector de voz normalmente puedes:

- filtrar por idioma
- filtrar por género
- elegir entre distintos tipos de voz
- escuchar vistas previas
- importar una voz de ElevenLabs

### Cómo importar la voz

1. En ElevenLabs, copia el **enlace compartido de VoiceLab** de la voz que quieres usar.
2. En Callin, abre el **selector de voz**.
3. Pega el enlace en el campo del enlace compartido.
4. Escribe un nombre interno en el campo para nombrar la voz importada.
5. Haz clic en el botón para agregar la voz.
6. Después de agregar la voz, selecciónala para el agente y guarda los cambios.

> **Consejo:** Usa un nombre interno claro como **Voz de soporte - Sofía** o **Voz de ventas - Inglés cálido** para que tu equipo la identifique rápidamente.

> **Importante:** Los filtros visibles y las voces disponibles pueden variar según tu cuenta, idioma o plan.

> **Error común:** Pegar un enlace normal de ElevenLabs en lugar del **enlace compartido de VoiceLab** puede impedir que la voz se importe correctamente.

Al elegir la voz, piensa en el tipo de experiencia que quieres transmitir. Un agente legal puede sonar mejor con una voz calmada y segura, mientras que un agente de hospitalidad puede funcionar mejor con una voz más cercana y dinámica.

### Velocidad

La velocidad controla lo rápido o despacio que habla el agente.

- valores más bajos hacen la voz más lenta
- valores más altos hacen la voz más rápida

Lo más recomendable suele ser un punto medio que suene natural y fácil de seguir.

### Nivel de variación

El nivel de variación ajusta lo predecibles o creativas que serán las respuestas.

- valores bajos hacen que el agente sea más estable y controlado
- valores altos hacen que las respuestas sean más variadas

En llamadas de negocio estructuradas, suele funcionar mejor una configuración baja o intermedia.

> **Consejo:** No pruebes solo la voz aislada. Haz una llamada completa y revisa cómo suena dentro del flujo real.

Esta sección permite que el agente haga algo más que hablar. Aquí defines acciones reales que pueden ocurrir durante la llamada o justo después.

### Programación de citas

Activa esta opción si el agente debe reservar citas durante la llamada.

Si todavía no configuraste esto antes, debes hacerlo aquí: [Google Calendar](https://app.callin.io/actions/google-calendar)

Esto es importante porque el agente necesita tener acceso a una configuración de calendario ya preparada antes de poder proponer horarios y confirmar reservas correctamente.

Un ejemplo simple: una clínica puede usar el agente para ofrecer huecos disponibles y dejar la cita confirmada durante la misma llamada.

### Transferencia de llamadas

Activa esta opción si el agente debe pasar la llamada a una persona real, a un departamento o a otro número.

Si todavía no configuraste esto antes, debes hacerlo aquí: [Transferencia de llamadas](https://app.callin.io/call-transfer)

Esto debe dejarse preparado con antelación para que el agente sepa a dónde transferir y bajo qué condición.

Un ejemplo práctico: el agente responde consultas sencillas, pero transfiere temas de facturación o casos urgentes a un equipo humano.

### Exclusión de llamadas

La exclusión permite que una persona indique que no quiere seguir recibiendo este tipo de llamadas.

Esto resulta útil en campañas de salida y en flujos repetitivos donde necesitas respetar la preferencia del contacto.

### Extracción de datos

La extracción de datos sirve para capturar información específica de la conversación.

Por ejemplo, puedes pedir al agente que extraiga:

- nombre
- fecha de cita
- nivel de interés
- mejor horario para devolver la llamada

Esto ayuda a que tu equipo no tenga que revisar toda la transcripción para encontrar los datos importantes.

### Envío posterior a la llamada

Esta opción sirve para enviar información de la llamada a otro sistema una vez que la conversación termina.

Es útil cuando quieres mandar resultados a un sistema externo, a un panel interno o a un flujo de automatización.

### Reintento de llamada

El reintento de llamada define qué debe pasar si la llamada no se completa correctamente o si se detecta un contestador.

Aquí puedes ajustar cuántos intentos realizar y cuánto esperar antes de volver a llamar.

### Rotación de números

La rotación de números permite repartir las llamadas entre varios números para distribuir mejor el tráfico y mejorar la entregabilidad.

Esto puede ser especialmente útil en operaciones de mayor volumen.

> **Importante:** Si no configuraste antes el calendario o la transferencia, primero debes hacerlo en sus páginas correspondientes y luego volver al agente para activar estas funciones correctamente.

Esta sección se utiliza cuando quieres que los visitantes hablen con el agente directamente desde tu sitio web.

### Fragmento de inserción

En la parte superior puedes copiar el fragmento de inserción y colocarlo en tu web. Ese código es el que carga el widget para tus visitantes.

Esto facilita que el equipo técnico o la persona que gestiona la web lo añada sin tener que reconstruir nada manualmente.

### Diseño y comportamiento

Aquí puedes decidir cómo aparecerá el widget.

Normalmente podrás elegir entre:

- mostrarlo integrado dentro de la página
- mostrarlo como un lanzador flotante

La mejor opción depende del uso real. Si quieres que el agente sea protagonista en una página concreta, suele funcionar mejor integrarlo directamente. Si quieres que esté disponible en todo el sitio sin ocupar espacio fijo, suele funcionar mejor un lanzador flotante.

### Modo de conversación

En esta parte defines si la interacción será por voz, por texto o por ambas opciones, según lo que tengas disponible en tu cuenta.

### Apariencia

Más abajo puedes personalizar detalles visuales como:

- tamaño
- colores
- transcripción en tiempo real
- botón de silencio
- estilo general

Esto es útil para que el widget encaje mejor con tu marca.

### Etiquetas y textos

También puedes personalizar textos visibles dentro del widget, como:

- texto principal
- texto para iniciar llamada
- texto para iniciar chat
- texto de conexión
- texto de escucha
- texto de finalización
- textos del chat
- mensajes vacíos
- textos de ayuda

Esto te permite adaptar la experiencia al tono real de tu negocio.

### Guardar y probar

Antes de publicar el widget, conviene seguir este orden:

1. guardar los cambios
2. revisar si hay errores
3. hacer una prueba real
4. confirmar que el texto, la voz y las acciones funcionan como esperas

> **Consejo:** Prueba el widget como si fueras un visitante real. Revisa tanto el flujo normal como casos menos perfectos, como interrupciones, dudas ambiguas o solicitudes fuera del alcance del agente.
