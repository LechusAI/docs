## Avant de commencer

Un agent **Enhanced** gère des flux complexes : intentions nuancées, instructions longues, capture de données fiable, et appels **entrants**, **sortants** ou **les deux**.

Si vous avez seulement besoin de **salutations**, de **FAQ simples**, ou de **capture de données basique** à faible coût, un agent **Basic** suffit.

**Actions externes (à configurer séparément, puis à relier) :**

- **Planification :** Google Calendar
- **Transferts :** Call Transfer

---

## Étape 1 — Créer l’agent

Allez dans **AI Agents → Create Agent → Start from Scratch**, saisissez un nom clair (ex. **Support FR – Sales**), sélectionnez **Version → Enhanced**, puis cliquez sur **Create Agent**.

**Bonne pratique :** nommez l’agent par **fonction + langue** pour éviter toute confusion plus tard.

---

## Étape 2 — Choisir le sens des appels : Entrants, Sortants ou Les deux

Dans **Agent → Call Direction**, choisissez ce qui correspond à votre activité :

- **Inbound (entrant)** : l’agent reçoit des appels.\
  Idéal pour : standard, support, accueil, lignes de service.\
  **Conseil :** activez **Transfer Call** pour escalader vers un humain si nécessaire.
- **Outbound (sortant)** : l’agent initie des appels.\
  Idéal pour : rappels, confirmations, enquêtes, relances, recouvrement.\
  **Conseil :** gardez les scripts courts et définissez des plages horaires autorisées.
- **Both Directions (les deux)** : un seul agent pour entrant + sortant.\
  Utile si le ton et la logique sont communs. **Nécessite plus de tests** pour éviter des objectifs mélangés.

**Réglez aussi :**

- **Maximum Call Duration (minutes)** : durée max avant raccrochage automatique (ex. **10**).
- **Greeting Message** : première phrase entendue par l’appelant.

**Exemple de greeting (en français) :**\
Bonjour, ici {{agent_name}}. Comment puis-je vous aider aujourd’hui ? Cet appel peut être enregistré à des fins de qualité.

---

## Étape 3 — Voix, langue et température

Dans **Voice & Language** :

- **Language / Secondary Language** : définissez une langue principale et, **uniquement si nécessaire**, une langue secondaire.
- **Voice** : choisissez un ton/accent adapté à votre marque.
- **Speed** : commencez sur **Normal**, ajustez après tests.
- **Temperature** : contrôle la créativité.

**Repères de température :**

- **0.2–0.5** = très déterministe (recommandé pour **prise de rendez-vous / conformité**)
- **0.6–0.8** = plus conversationnel (FAQ, vente)

Utilisez **Test Call** pour écouter et ajuster.

---

## Étape 4 — LLM : ce que c’est et comment choisir

**Définition :** le **LLM (Large Language Model)** est le “cerveau” qui comprend et rédige les réponses. **Enhanced** permet de choisir le modèle/fournisseur pour équilibrer **précision**, **latence** et **coût**.

**Règle rapide :**

- Flux courts/simples (triage, FAQ) → modèle **rapide / économique**
- Flux multi-étapes + extraction de données → modèle **équilibré**
- Tâches longues, multilingues, haute précision → modèle **avancé**

**Signaux pour ajuster :**

- Réponses vagues/incohérentes → montez en gamme
- Réponses correctes mais trop lentes/chères → descendez en gamme

Pour la prise de rendez-vous et les formulaires : combinez un **LLM stable** + **température basse**.

**Important :** définissez aussi la **Timezone** de l’agent pour correspondre à vos clients ou au calendrier afin d’éviter des rendez-vous à la mauvaise heure.

---

## Étape 5 — Prompt de conversation (script opératoire)

Donnez à l’agent : **objectifs**, **ton**, **règles**.

### Objectif

1. Accueil chaleureux, identifier la raison en **1–2 questions**.
2. Résoudre ou router : **planifier**, **transférer** ou **envoyer un résumé**.
3. Confirmer les informations critiques (nom, téléphone, date/heure).

### Style

Langage simple, empathique, sans jargon. Résumer la prochaine étape à la fin.

### Règles

Ne pas demander de données sensibles. Transférer si l’utilisateur le demande ou si l’agent est bloqué.

### Tools

Utiliser **Google Calendar** et **Transfer** uniquement si approprié et après confirmation.

---

## Étape 6 — Call Actions

### 6.1 Planifier sur Google Calendar

D’abord, configurez l’intégration Google Calendar et activez **Appointments** sur le calendrier choisi.

Dans **Call Action**, activez **Schedule Appointment on Google Calendar** et sélectionnez le calendrier (icône **gear** si disponible).

**Phrase de booking (en français) :**\
Je peux vous proposer mardi à 10h30 ou mercredi à 12h00 (heure locale). Qu’est-ce qui vous convient le mieux ?

---

### 6.2 Transférer l’appel (Transfer Call)

Créez une configuration dans **Call Transfer** (numéro de destination, horaires, file d’attente).

Dans **Call Action**, activez **Transfer Call** et sélectionnez cette configuration.

**Phrase de transfert (en français) :**\
Je vous mets en relation avec la bonne personne. Merci de rester en ligne.

---

### 6.3 Extraction de données (Data Extraction)

Dans **Call Action → Data Extraction**, définissez les champs à capturer, par exemple :

- **firstName** : prénom
- **appointmentDate** : date/heure du rendez-vous
- **issueType** : raison principale (ex. facturation, support, vente)

Ensuite, mentionnez ces champs dans votre prompt et donnez 1–2 exemples pour aider l’agent à extraire correctement.

---

### 6.4 Webhook post-appel (Post-Call Webhook)

Activez-le pour envoyer les détails de l’appel à votre système.

Exemple de données typiques envoyées :

- Nom de l’agent
- Sens de l’appel (entrant/sortant/les deux)
- Valeurs extraites (prénom, date/heure, motif)
- Liens vers l’enregistrement et la transcription

---

## Étape 7 — Paramètres d’appel (Call Settings)

Dans **Call Settings** :

- **Record Calls** : enregistrer audio + transcription (recommandé pour QA/conformité)
- **Voicemail Detection** : raccrocher sur répondeur pour économiser des minutes
- **Background Ambience** : léger bruit de fond pour un rendu naturel
- **Greeting Message Delay (ms)** : petite pause avant la salutation (ex. **1200**)

---

## Étape 8 — Tester et enregistrer

Lancez **Test Call** dans chaque onglet (Agent, Voice & Language, Call Action). Vérifiez : salutation, langue, vitesse, prise de RDV, transfert, entités.

Cliquez sur **Save**, puis faites un **appel réel** de vérification. Contrôlez dans **Call History** : enregistrement, transcription, valeurs extraites.

---

## Configuration avancée (optionnel)

- **Routage par mots-clés** : définissez dans le prompt les mots qui déclenchent la prise de RDV (réserver, reprogrammer) ou le transfert (parler à un humain, superviseur).
- **Double confirmation** : faites répéter date/heure avant de réserver.
- **Multilingue** : n’activez **Secondary Language** que si vous servez réellement deux langues.
- **Température selon objectif** : basse pour RDV/transfert, moyenne pour FAQ/vente.

---

## Erreurs fréquentes et correctifs

- **“This calendar does not have an appointment action.”**\
  Le calendrier n’a pas **Appointments** activé. Activez-le dans Google Calendar ou utilisez un autre calendrier.
- **Bannière : “Select a Google Calendar…”**\
  Dans **Call Action**, ouvrez l’icône **gear** sur **Schedule Appointment** et sélectionnez le bon calendrier.
- **Bannière : “Select a Transfer Configuration…”**\
  Créez et enregistrez une config dans **Call Transfer**, puis sélectionnez-la dans l’agent.
- **Rendez-vous à la mauvaise heure**\
  Alignez **Timezone** (agent + calendrier) et confirmez l’heure locale de l’appelant.
- **Mélange de langues**\
  Gardez le prompt dans **une seule langue**, réglez correctement **Language/Secondary Language**, et choisissez une **Voice** cohérente.
- **Entités manquantes**\
  Définissez des types clairs, ajoutez des exemples dans le prompt, baissez la température, ou choisissez un LLM plus capable.
- **Webhook activé sans URL (“Webhook Url is required…”)**\
  Ajoutez un endpoint valide avant d’activer **Post-Call Webhook**, ou désactivez-le pendant les tests.

---

## Conclusion

Votre agent **Enhanced** peut maintenant gérer des contextes complexes, réserver correctement, escalader vers un humain et envoyer des données propres vers vos systèmes. Commencez avec un modèle équilibré, testez sur de vrais appels, puis ajustez : cette base vous permettra de passer à l’échelle sans friction.
