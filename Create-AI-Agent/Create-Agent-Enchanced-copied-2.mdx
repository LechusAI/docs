## Vue d’ensemble

La page **Agents d’IA** est le point de départ pour créer et gérer les agents de votre compte. Depuis cette page, vous pouvez voir tous vos agents au même endroit, ouvrir n’importe lequel pour le modifier et repérer rapidement les configurations encore incomplètes.

Dans cette vue, vous pouvez généralement :

- créer un nouvel agent
- filtrer les agents selon le type d’appel
- rechercher un agent par nom
- vérifier si un agent possède déjà un numéro attribué
- accéder directement à la configuration pour terminer les réglages

C’est particulièrement utile lorsque vous gérez plusieurs parcours différents. Par exemple, une clinique peut avoir un agent pour rappeler les rendez-vous, un autre pour répondre aux appels entrants et un autre pour relancer les opportunités perdues. Les séparer par fonction rend les tests, les vérifications et les modifications futures beaucoup plus simples.

Pour créer un nouvel agent, cliquez sur le bouton de création, choisissez si vous souhaitez partir de zéro ou utiliser un modèle, saisissez un nom clair, puis confirmez la création.

> **Conseil :** Utilisez des noms qui décrivent le rôle réel de l’agent, comme **Agent de rappel de rendez-vous** ou **Agent de qualification des patients**, plutôt que des noms génériques comme « Test ».

Cette première section constitue la base de toute la configuration. C’est ici que vous définissez le rôle de l’agent, sa manière de parler, son objectif et les éléments supplémentaires qu’il peut utiliser pendant l’appel.

### Direction des appels

La direction des appels définit si l’agent :

- appelle les utilisateurs
- répond aux appels entrants
- fait les deux

Vous devez choisir cette option en fonction du cas réel. Par exemple, un agent chargé de rappeler un paiement ou un rendez-vous est généralement utilisé pour les appels sortants, tandis qu’un agent qui répond aux questions ou gère les réservations est généralement utilisé pour les appels entrants.

### Durée maximale de l’appel

La durée maximale de l’appel détermine combien de temps une conversation peut durer avant de se terminer automatiquement.

Cela vous aide à :

- garder des appels efficaces
- éviter les conversations trop longues
- mieux contrôler l’utilisation

À titre indicatif, un appel de rappel court peut nécessiter entre **3 et 5 minutes**, tandis qu’un appel de réservation ou de qualification peut nécessiter entre **5 et 10 minutes**.

### Message d’accueil

Le message d’accueil est la première chose que la personne entend au début de l’appel. Il doit être court, clair et lié au rôle réel de l’agent.

Une structure simple fonctionne souvent très bien :

- salutation
- présentation
- raison de l’appel
- invitation à continuer

Exemple :

**Bonjour, je vous appelle de la clinique Northwind pour vous aider à confirmer votre prochain rendez-vous. Est-ce que c’est un bon moment pour continuer ?**

Si vous utilisez des variables dynamiques, vous pouvez réutiliser la même structure dans plusieurs agents sans devoir tout réécrire à chaque fois.

### Instructions de conversation

Les instructions de conversation sont l’une des parties les plus importantes de la configuration. Alors que le message d’accueil ouvre l’appel, ces instructions définissent le comportement de l’agent pendant tout le reste de l’échange.

Une manière simple de le comprendre est la suivante :

- le **message d’accueil** démarre la conversation
- les **instructions de conversation** guident tout ce qui se passe ensuite

L’exemple affiché par défaut dans Callin est utile parce qu’il montre une structure recommandée. Il n’est pas nécessaire de le recopier tel quel, mais il est important de comprendre pourquoi il est organisé de cette façon.

#### Structure habituelle

L’exemple de base est généralement divisé en blocs comme :

- personnalité
- contexte
- ton
- objectif
- limites
- outils

Chaque bloc a un rôle précis.

#### Personnalité

Ici, vous expliquez qui est l’agent et comment il doit se présenter.

Par exemple :

- un assistant d’accueil
- un assistant de réservation
- un assistant de suivi
- un assistant de qualification

Cela aide l’agent à garder une identité cohérente pendant tout l’appel.

#### Contexte

Ici, vous expliquez dans quel contexte les conversations ont lieu.

Par exemple :

- des appels téléphoniques courts où la clarté est essentielle
- des appels pour prendre des rendez-vous
- des appels de suivi
- des appels pour répondre à des questions simples

Ce bloc aide l’agent à comprendre le type d’échange qu’il gère et à ne pas répondre comme un assistant générique.

#### Ton

Ici, vous définissez la manière dont l’agent doit s’exprimer.

L’exemple par défaut montre clairement que, pour les appels vocaux, il est généralement préférable que l’agent :

- parle de manière polie et concise
- utilise de brèves confirmations
- garde un ton chaleureux mais professionnel
- fasse des pauses naturelles
- énonce clairement les données structurées, comme les adresses électroniques

C’est important parce qu’un appel téléphonique demande des réponses plus claires et plus directes qu’un échange écrit.

#### Objectif

Ici, vous expliquez ce que l’agent doit accomplir.

Par exemple :

- confirmer un rendez-vous
- répondre aux questions fréquentes
- recueillir des informations de base
- qualifier un prospect
- conduire la conversation vers l’étape suivante appropriée

Sans objectif clair, l’agent peut bien s’exprimer sans pour autant remplir sa mission.

#### Limites

Ici, vous indiquez ce que l’agent ne doit pas faire.

L’exemple de base montre des règles très utiles, comme :

- ne pas partager d’informations sensibles
- ne pas inventer de réponses
- reconnaître ses limites lorsqu’il ne peut pas aider
- rester calme si l’utilisateur se montre frustré
- rester concentré sur le besoin réel de l’utilisateur

Cette partie est essentielle si l’agent parle directement à des clients ou à des patients.

#### Outils dans les instructions

L’exemple comprend aussi un bloc qui indique si l’agent doit fonctionner uniquement par la conversation ou s’il peut s’appuyer sur des outils déjà configurés.

Si l’agent doit tout résoudre en parlant, il est préférable de le dire clairement. S’il doit utiliser un outil, cet outil doit exister avant d’être associé à l’agent.

### Comment bien rédiger les instructions de conversation

De bonnes instructions doivent expliquer le travail de l’agent de manière claire et concrète.

Au lieu d’écrire quelque chose de trop général comme :

**Soyez utile et poli.**

Il vaut mieux écrire quelque chose de plus précis, par exemple :

**L’agent est un assistant téléphonique pour une clinique dentaire. Il doit aider à confirmer les rendez-vous, répondre aux questions simples sur les horaires, garder un ton poli et concis, et orienter la personne vers l’étape suivante lorsque la demande dépasse son périmètre.**

Cela fonctionne mieux parce que cela définit :

- qui est l’agent
- quel type d’appel il gère
- comment il doit s’exprimer
- quel résultat il doit chercher
- ce qu’il doit éviter

### Optimiser les instructions

À côté de la zone des instructions, Callin propose une option pour **optimiser les instructions**. Lorsque vous l’ouvrez, une fenêtre apparaît pour vous permettre d’indiquer le type d’amélioration que vous souhaitez appliquer au texte actuel.

C’est utile lorsque vous avez déjà une base, mais que vous voulez l’améliorer sans tout réécrire depuis le début.

Par exemple, vous pouvez demander au système de :

- rendre le texte plus court et plus clair
- utiliser un ton plus proche
- ajouter une gestion des objections
- donner une impression plus professionnelle
- simplifier des instructions trop longues

Un exemple pratique serait de demander quelque chose comme :

**Rendez le texte plus concis, conservez un ton chaleureux et professionnel, et ajoutez une gestion plus claire des objections fréquentes.**

Après l’optimisation, relisez toujours le résultat avant d’enregistrer afin de vérifier qu’il reste bien aligné sur le rôle réel de l’agent.

> **Important :** L’optimisation aide à améliorer la rédaction, mais elle ne remplace pas une vérification humaine. Avant d’enregistrer, assurez-vous que le texte final correspond réellement au comportement souhaité.

### Variables dynamiques

Les variables dynamiques vous permettent de réutiliser des informations comme le nom de l’agent ou celui de l’entreprise dans plusieurs parties de la configuration.

C’est utile lorsque vous souhaitez conserver la même structure pour plusieurs agents et ne modifier que certaines valeurs.

### Fuseau horaire et modèle

Plus bas, vous pouvez configurer le fuseau horaire et le modèle utilisé par l’agent.

Le fuseau horaire est important lorsque l’agent :

- mentionne des horaires
- planifie des rendez-vous
- fait référence à des heures locales

Le modèle influence la manière dont les réponses sont générées. Selon votre compte ou votre offre, certaines options peuvent varier.

### Base de connaissances

La base de connaissances fournit à l’agent des informations d’appui pour répondre avec plus de précision.

Si vous ne l’avez pas encore configurée, vous devez d’abord le faire ici : [Base de connaissances](https://app.callin.io/knowledge-base)

C’est l’endroit approprié pour ajouter du contenu comme :

- des questions fréquentes
- des politiques
- des tarifs
- des détails de service
- des informations utiles pour répondre aux questions courantes

Par exemple, une clinique peut y inclure ses horaires d’ouverture, ses règles d’annulation, les assurances acceptées et les consignes avant un rendez-vous.

Une règle pratique est la suivante :

- utilisez les **instructions de conversation** pour le comportement et les règles
- utilisez la **base de connaissances** pour les faits et les informations de référence

### Outils

Les outils permettent à l’agent d’utiliser des fonctions supplémentaires pendant un appel.

Si vous n’avez pas encore configuré l’outil, vous devez d’abord le faire ici : [Outils](https://app.callin.io/tools)

C’est important, car l’agent ne peut pas utiliser correctement un outil qui n’existe pas encore ou qui n’a pas été préparé auparavant.

Un déroulement recommandé est le suivant :

1. configurer l’outil dans [Outils](https://app.callin.io/tools)
2. revenir à l’agent
3. associer l’outil
4. tester la conversation complète

Par exemple, si vous souhaitez que l’agent consulte une information externe ou exécute une action précise, vous devez d’abord préparer cet outil.

### Paramètres d’appel

Dans cette même section, vous pouvez aussi trouver des paramètres supplémentaires, comme :

- l’enregistrement des appels
- la détection de la messagerie vocale
- l’option permettant à l’utilisateur de parler en premier

Ces paramètres définissent plus finement l’expérience réelle une fois l’agent activé.

> **Erreur fréquente :** Rédiger des instructions trop générales et penser que l’agent saura automatiquement quand utiliser un outil. L’objectif doit être clair dans les instructions et l’outil doit être configuré au préalable.

La section voix et langue contrôle la manière dont l’agent parle et traite la conversation.

### Langue principale et langue secondaire

Commencez par choisir la langue principale. Elle doit correspondre à la langue que la majorité des personnes utilisera pour parler avec l’agent.

Vous pouvez également ajouter une langue secondaire si l’agent doit prendre en charge plus d’une langue.

Par exemple :

- une clinique locale peut n’avoir besoin que d’une langue principale
- une entreprise qui s’adresse à plusieurs publics peut combiner deux langues

### Voix

La voix définit la manière dont l’agent sonnera pendant l’appel.

Dans le sélecteur de voix, vous pouvez généralement :

- filtrer par langue
- filtrer par genre
- choisir entre différents types de voix
- écouter des aperçus
- importer une voix depuis ElevenLabs

Si vous utilisez une voix importée, il est préférable de lui donner un nom clair afin de la retrouver facilement plus tard.

Lorsque vous choisissez la voix, pensez au type d’expérience que vous souhaitez transmettre. Un agent juridique peut mieux fonctionner avec une voix calme et assurée, tandis qu’un agent pour l’hôtellerie peut être plus efficace avec une voix plus proche et dynamique.

### Vitesse

La vitesse contrôle le débit de parole de l’agent.

- des valeurs plus basses rendent la voix plus lente
- des valeurs plus élevées rendent la voix plus rapide

Le plus recommandé est généralement un point d’équilibre qui reste naturel et facile à suivre.

### Niveau de variation

Le niveau de variation ajuste le degré de prévisibilité ou de créativité des réponses.

- des valeurs basses rendent l’agent plus stable et plus contrôlé
- des valeurs élevées rendent les réponses plus variées

Dans des appels professionnels structurés, un réglage faible ou intermédiaire fonctionne généralement mieux.

> **Conseil :** Ne testez pas seulement la voix isolément. Faites un appel complet et vérifiez comment elle sonne dans le flux réel.

Cette section permet à l’agent de faire autre chose que simplement parler. Vous y définissez des actions concrètes qui peuvent se produire pendant l’appel ou juste après.

### Prise de rendez-vous

Activez cette option si l’agent doit réserver des rendez-vous pendant l’appel.

Si vous ne l’avez pas encore configurée, vous devez d’abord le faire ici : [Google Calendar](https://app.callin.io/actions/google-calendar)

C’est important, car l’agent doit avoir accès à une configuration de calendrier déjà prête avant de pouvoir proposer des créneaux et confirmer correctement une réservation.

Exemple simple : une clinique peut utiliser l’agent pour proposer des disponibilités et confirmer le rendez-vous pendant le même appel.

### Transfert d’appel

Activez cette option si l’agent doit transférer l’appel à une personne réelle, à un service ou à un autre numéro.

Si vous ne l’avez pas encore configurée, vous devez d’abord le faire ici : [Transfert d’appel](https://app.callin.io/call-transfer)

Cela doit être préparé à l’avance pour que l’agent sache où transférer et dans quel cas.

Exemple pratique : l’agent répond à des questions simples, mais transfère les questions de facturation ou les cas urgents à une équipe humaine.

### Exclusion des appels

L’exclusion permet à une personne d’indiquer qu’elle ne souhaite plus recevoir ce type d’appel.

C’est utile dans les campagnes sortantes et dans les parcours répétitifs où vous devez respecter la préférence du contact.

### Extraction de données

L’extraction de données sert à capturer des informations précises à partir de la conversation.

Par exemple, vous pouvez demander à l’agent d’extraire :

- le nom
- la date du rendez-vous
- le niveau d’intérêt
- le meilleur créneau pour rappeler

Cela évite à votre équipe de devoir relire toute la transcription pour retrouver les données importantes.

### Envoi après l’appel

Cette option permet d’envoyer les informations de l’appel vers un autre système une fois la conversation terminée.

C’est utile si vous souhaitez transmettre les résultats à un système externe, à un tableau de bord interne ou à un flux d’automatisation.

### Relance d’appel

La relance d’appel définit ce qui doit se passer si l’appel n’aboutit pas correctement ou si une messagerie est détectée.

Vous pouvez régler le nombre de tentatives et le délai avant le prochain essai.

### Rotation des numéros

La rotation des numéros permet de répartir les appels entre plusieurs numéros afin de mieux distribuer le trafic et d’améliorer la délivrabilité.

Cela peut être particulièrement utile pour des opérations à volume élevé.

> **Important :** Si vous n’avez pas encore configuré le calendrier ou le transfert, faites-le d’abord dans leurs pages respectives, puis revenez à l’agent pour activer correctement ces fonctions.

Cette section est utilisée lorsque vous souhaitez permettre aux visiteurs de parler directement avec l’agent depuis votre site web.

### Code d’intégration

En haut de la section, vous pouvez copier le code d’intégration et le placer sur votre site. C’est ce code qui charge le widget pour vos visiteurs.

Cela permet à l’équipe technique ou à la personne qui gère le site de l’ajouter sans avoir à reconstruire quoi que ce soit manuellement.

### Présentation et comportement

Ici, vous pouvez décider de la manière dont le widget apparaîtra.

En général, vous pourrez choisir entre :

- l’afficher intégré dans la page
- l’afficher sous forme de lanceur flottant

Le meilleur choix dépend de l’usage réel. Si vous souhaitez que l’agent soit mis en avant sur une page précise, il est souvent préférable de l’intégrer directement. Si vous voulez qu’il reste disponible sur tout le site sans occuper d’espace fixe, un lanceur flottant est souvent plus adapté.

### Mode de conversation

Dans cette partie, vous définissez si l’interaction se fera par la voix, par le texte ou par les deux, selon les options disponibles sur votre compte.

### Apparence

Plus bas, vous pouvez personnaliser des éléments visuels comme :

- la taille
- les couleurs
- la transcription en temps réel
- le bouton de coupure du son
- le style général

Cela est utile pour mieux intégrer le widget à votre image de marque.

### Libellés et textes

Vous pouvez également personnaliser les textes visibles dans le widget, comme :

- le texte principal
- le texte pour démarrer un appel
- le texte pour démarrer une discussion
- le texte de connexion
- le texte d’écoute
- le texte de fin
- les textes de discussion
- les messages vides
- les textes d’aide

Cela vous permet d’adapter l’expérience au ton réel de votre activité.

### Enregistrer et tester

Avant de publier le widget, il est recommandé de suivre cet ordre :

1. enregistrer les modifications
2. vérifier s’il y a des erreurs
3. effectuer un test réel
4. confirmer que le texte, la voix et les actions fonctionnent comme prévu

> **Conseil :** Testez le widget comme si vous étiez un véritable visiteur. Vérifiez le parcours normal, mais aussi les cas moins parfaits, comme les interruptions, les demandes ambiguës ou les requêtes hors du périmètre de l’agent.
